# Глобальные типы и SVGR

[← Документация](README.md)

Глобальные декларации находятся в `src/ambient`. В `styles.d.ts` объявлены побочные импорты `*.css`, которые проверяет TypeScript 6; типы CSS Modules по-прежнему предоставляет Next.js.

## SVG как React-компоненты

Правило `turbopack.rules["*.svg"]` в `next.config.ts` передаёт SVG-файлы загрузчику `@svgr/webpack`. Команды `bun run dev` и `bun run build` используют Turbopack. Опция `icon: true` задаёт стандартные размеры иконки `1em`; размеры можно переопределить пропсами.

После добавления SVG-файла, например `src/shared/assets/images/logo.svg`, его можно использовать так:

```tsx
import Logo from "@images/logo.svg";

export function Brand() {
  return <Logo className="size-6" fill="currentColor" aria-label="Логотип" />;
}
```

Декларация `src/ambient/svg.d.ts` задаёт тип компонента с пропсами `SVGProps<SVGSVGElement>`. Редактор подсказывает SVG-атрибуты, а обработчики событий получают тип корневого SVG-элемента. Неизвестные пропсы и неверные значения атрибутов вызывают ошибку TypeScript.

Файл декларации указан **перед `next-env.d.ts`** в массиве `include` файла `tsconfig.json`. Это порядок, [рекомендованный SVGR](https://react-svgr.com/docs/next/#typescript): собственная декларация должна иметь приоритет над стандартным типом `any` для SVG в Next.js.

Импорт типов React находится внутри `declare module "*.svg"`. Не добавляйте в этот файл импорты или `export {}` на верхнем уровне: они превратят его в модуль, и декларация станет расширением существующего модуля вместо объявления файлов `*.svg`.

Текущая конфигурация обрабатывает обычные импорты `*.svg` как компоненты. Для SVG по URL используйте файл в `public`, например `<img src="/logo.svg" alt="Логотип" />`. Импорты `*.svg?url` требуют отдельного правила загрузчика и соответствующей декларации типов.

## Расширение глобальных интерфейсов

Для расширения `Window`, `NodeJS.ProcessEnv` и других глобальных интерфейсов создайте отдельный файл `src/ambient/global.d.ts`. Здесь, в отличие от декларации SVG, нужен модуль с блоком `declare global`:

```ts
export {};

declare global {
  interface Window {
    analytics?: (event: string) => void;
  }
}
```

Для расширения типов сторонней библиотеки используйте отдельную декларацию с импортом этой библиотеки и `declare module "имя-библиотеки"`. Типы предметной области экспортируйте из обычных `.ts`-модулей через public API соответствующего FSD-слайса.

Файл `next-env.d.ts` генерируется Next.js и не редактируется вручную. Новые `.d.ts`-файлы в `src/ambient` автоматически попадают под `**/*.ts` в `tsconfig.json`; SVG-декларация дополнительно указана первой для приоритета.
